# AE 中英文切换器设计

日期：2026-08-08

## 目标

创建一个原生 macOS 小工具，自动识别本机安装的 Adobe After Effects 版本、构建号、可用语言资源、当前有效语言和运行状态，并在简体中文与 English 之间安全切换。

首个版本直接服务当前 Mac，同时保持标准的 SwiftUI 工程结构，以便后续加入 Developer ID 签名、Apple 公证和分发。

## 已确认的产品范围

- 独立的 macOS 窗口应用，不常驻菜单栏。
- 自动列出 `/Applications` 中全部正式版和 Beta 版 After Effects。
- 下拉菜单用于查看各版本的版本号、构建号、语言资源和运行状态。
- 若 AE 正在运行，切换前提示用户退出；不强制结束进程。
- 中文切换仅在系统默认语言及 AE 中文资源满足要求时开放。
- 英文切换使用 Adobe 支持的用户文稿目录标记文件。
- 不修改 AE 应用包、不替换语言资源、不申请管理员权限。

## 平台与技术选型

- 平台：macOS。
- UI：SwiftUI。
- 语言：Swift。
- 工程：Swift Package 驱动的 macOS App，业务逻辑与界面分离，便于单元测试和后续签名分发。
- 最低系统版本：macOS 13。当前实现不依赖第三方库。

## 关键事实与限制

Adobe 的 `ae_force_english.txt` 位于当前用户的 `Documents` 根目录。存在时 AE 以英文启动，移除时恢复 AE 的默认语言。该文件是用户级全局开关，不属于某个 AE 版本，因此切换会影响此用户下所有已安装的 AE 版本。

应用会清楚显示“语言切换影响全部 AE 版本”。版本下拉菜单只负责查看安装信息和运行状态，不承诺逐版本独立语言。

Adobe 对简体中文有额外要求：AE 必须包含 `zh_CN` 资源，且 macOS 的首选显示语言必须为简体中文。若条件不足，应用阻止“切换中文”，说明缺少的条件，并提供打开“语言与地区”设置及 Adobe 安装说明的入口。

参考：

- Adobe 官方简体中文安装说明：https://helpx.adobe.com/after-effects/desktop/get-started/language-support/install-launch-after-effects-simplified-chinese-japanese-languages.html
- Adobe UI 语言支持说明：https://helpx.adobe.com/in/after-effects/using/improved-ui-language-support.html
- Adobe 社区确认的英文标记方法：https://community.adobe.com/t5/after-effects-discussions/ui-language-in-after-effects-2018/m-p/9543077

## 架构

### `AfterEffectsScanner`

扫描 `/Applications` 下名称匹配 `Adobe After Effects*.app` 的主程序，排除 Render Engine 等辅助应用。读取每个应用的 `Info.plist`，得到显示名称、完整版本、构建号、Bundle Identifier 和路径。

扫描应用包内的本地化目录与字典资源，至少识别 `zh_CN` 和 `en_US` 是否可用。无法读取某个应用时保留其他有效结果，并为该条目显示具体错误。

扫描结果按语义版本从高到低排序。未找到 AE 时显示空状态与“重新扫描”按钮。

### `LanguageStateDetector`

读取：

- `~/Documents/ae_force_english.txt` 是否存在；
- macOS `AppleLanguages` 的首选语言；
- 已选 AE 的 `zh_CN`、`en_US` 资源是否存在。

状态规则：

- 标记文件存在：当前有效语言为 English。
- 标记文件不存在，系统首选语言为简体中文且 AE 包含中文资源：当前有效语言为简体中文。
- 其他情况：显示“默认语言：<检测值>”，并将中文切换标记为不可用。

由于开关是全局的，界面顶部的当前语言状态对所有已安装版本一致。

### `LanguageSwitcher`

切换到 English 时，以原子方式在用户 `Documents` 目录创建空的 `ae_force_english.txt`。若已有同名普通文件，则视为英文已启用且不覆盖其内容；若同名路径为目录或符号链接，则停止并报告。

切换到简体中文时，仅自动删除零字节的同名普通文件。删除前确认中文先决条件满足；若文件非空，或路径是目录、符号链接及其他异常类型，则停止并报告，交由用户自行检查，不做破坏性处理。

切换成功后立即重新检测状态，并提示“下次启动 AE 生效”。

### `AfterEffectsProcessMonitor`

通过 `NSWorkspace` 的运行中应用列表识别 After Effects 主程序。若任一 AE 正在运行，切换按钮触发确认对话框，要求用户自行退出 AE；应用持续刷新状态，所有 AE 退出后才允许继续。

不发送强制终止信号，不处理未保存工程。

### SwiftUI 界面

单窗口布局：

1. 标题与全局当前语言状态。
2. AE 版本下拉菜单。
3. 版本详情：完整版本、构建号、安装路径、中文/英文资源、运行状态。
4. 醒目说明：“语言设置会影响当前用户的全部 AE 版本。”
5. 两个主按钮：“切换到中文”和“Switch to English”。当前语言对应按钮禁用。
6. 底部状态消息、重新扫描按钮和帮助入口。

界面默认使用简体中文；英文按钮保留英文文案，降低操作歧义。

## 数据流

启动时扫描 AE → 读取系统与标记文件 → 计算全局语言状态 → 展示版本列表和按钮状态。

用户点击切换 → 检查 AE 是否运行 → 检查目标语言前置条件 → 创建或删除标记文件 → 重新检测 → 展示结果。

应用重新获得焦点时刷新运行状态和语言状态，以反映用户在外部完成的退出、文件修改或系统设置变化。

## 错误处理

- 没有安装 AE：显示明确空状态，不展示可执行的切换按钮。
- 无法访问 `Documents`：展示系统错误和目标路径，不反复重试。
- 中文资源缺失：禁止中文切换，建议通过 Creative Cloud 重新安装中文资源。
- 系统首选语言不是简体中文：禁止中文切换，提供设置说明。
- AE 正在运行：提示退出，不强制关闭。
- 标记路径类型异常：停止操作，避免删除目录或符号链接。
- 扫描到损坏或不完整的 AE：该版本显示为不可用，不影响其他版本。

## 测试策略

业务逻辑通过协议注入文件系统、应用扫描器、系统语言提供器和进程监视器，避免测试依赖真实 AE 安装。

单元测试覆盖：

- 多版本发现、辅助应用排除和语义版本排序；
- 版本号与构建号读取；
- 中英文资源检测；
- 英文标记存在、缺失及异常类型；
- 简体中文可用与不可用条件；
- 创建英文标记与安全移除；
- AE 运行时阻止切换；
- 文件权限错误及部分损坏安装。

集成验证使用临时目录模拟应用包和用户文稿目录。最终在当前机器上做只读实机扫描验证；实际语言切换由用户在应用中主动点击，不在自动测试中更改真实设置。

## 验收标准

- 当前机器上识别出 Adobe After Effects 2026，显示 `26.0.0` 和构建号 `26.0.0.67`。
- 正确识别当前 macOS 首选语言为简体中文，并识别 AE 的 `zh_CN` 与 `en_US` 资源。
- 英文标记存在时显示 English，不存在且中文条件满足时显示简体中文。
- 点击英文切换可安全创建标记；点击中文切换可安全移除普通标记文件。
- AE 运行时不修改语言状态，并提示先退出。
- 多版本下拉列表工作正常，界面明确说明语言切换为全局操作。
- 应用不修改 `/Applications` 内文件，不要求管理员权限。
- 所有自动化测试通过，并产出可双击运行的 `.app`。

## 暂不包含

- Windows 版本。
- 菜单栏常驻模式。
- 自动强制退出 AE。
- 自动修改整个 macOS 的首选语言。
- 自动卸载或重装 AE。
- 逐版本独立语言设置。
- 首版签名、公证和自动更新；仅保留后续接入结构与说明。
